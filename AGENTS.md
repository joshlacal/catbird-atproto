# AGENTS.md

Agent instructions for this repository (`CLAUDE.md` imports this file).

## Overview

`catbird-atproto` is the **shared AT Protocol type surface for every Rust crate** in the workspace. It is a standalone Rust library crate (`catbird-atproto`, edition 2021) whose entire public API is **generated from Lexicon schemas** by [Jacquard](https://tangled.org/nonbinary.computer/jacquard) (`jacquard-lexicon` / `jacquard-common` / `jacquard-derive`, pinned to git rev `3287244a99262a361bd32873a871982da0a76c40`, version 0.13.0).

- Path dependency only — never published. Consumers pull it in via `path = "..."` (see [Consumers](#consumers)).
- The crate is buildable in isolation and does **not** depend on `audiopus_sys`, so it compiles in ~2s with no CMake workaround needed.
- Generated AT Protocol namespaces live under `src/generated/`. Everything in there is machine-output — **do not hand-edit** (see [Codegen](#codegen-is-source-of-truth)).

## Build & Test

```bash
cd catbird-atproto
cargo build
cargo check          # fast iteration
cargo test

# Feature flags
cargo build --features streaming     # enables websocket + DAG-CBOR (serde_ipld_dagcbor)
cargo build --features namespace-site-standard
cargo build --no-default-features    # drops the blue_catbird namespace

# Lint/format
cargo fmt --check && cargo clippy --all-targets --all-features
```

Features (`Cargo.toml`):
- `namespace-bluecatbird` (**default**) — gates the `blue_catbird` (`blue.catbird.*`) namespace.
- `namespace-site-standard` — gates the `site_standard` (`site.standard.*`) namespace and the `com_atproto` types it references.
- `namespace-atproto-space` — gates the `com.atproto.space`, `com.atproto.memberspace`, `com.atproto.managedspace` and `com.atproto.personalspace` (permissioned-data Spaces) modules. `Scripts/regenerate.py` adds this gate after generation. The October 29, 2026 alpha removed `com.atproto.simplespace`; its methods moved to `space` (create/update/get/delete) and `memberspace`/`managedspace` (members, checkUserAccess).
- `streaming` — pulls in `jacquard-common/websocket` + `serde_ipld_dagcbor` for firehose/event-stream consumers.

## Codegen Is Source of Truth

**Never hand-edit anything under `src/generated/`.** Every file there carries `// @generated by jacquard-lexicon. DO NOT EDIT.` and is overwritten on the next regeneration. To change a type, edit the **Lexicon JSON**, then regenerate.

### Lexicon source

The canonical Rust codegen reads the same split corpus as the Swift/Kotlin generator after the Petrel restructure:

1. **Petrel core/reference**: `Petrel/generator/lexicons/`
2. **Catbird overlay**: `PetrelCatbird/lexicons/`

`mls-codegen` stages those directories in order, so later overlay files shadow earlier core files with the same relative path. `mls-ds/lexicon/` is legacy input for scoped server-era regeneration and must not be used as the canonical catbird-atproto regeneration source.

### Regenerate

There is **one canonical regeneration command**: `Scripts/regenerate.py` in this repository, run with the `gen-lexicons` binary of `mls-codegen` (`mls-ds/codegen/`). Run it from this repository with `Petrel/`, `PetrelCatbird/` and `mls-ds/` checked out beside it; the script reads `../Petrel/generator/lexicons` and `../PetrelCatbird/lexicons` by default.

The generator must come from **mls-ds at or after the generator fixes `11abdd83d` and `ee9b1686`**. `11abdd83d` gives fields that refer to a named bytes definition (`#artifactHash`, `#identifierBytes`) the same codec as inline bytes, so JSON accepts `$bytes` and DAG-CBOR writes byte strings. `ee9b1686` gives the schemaless `labyrinthRelay` output its raw-body codec. The script no longer patches either codec in, so an older generator produces wrong codecs; `check` reports the drift, and `tests/named_bytes_contract.rs` and `tests/labyrinth_relay_contract.rs` cover both.

```bash
# Checkpoint first — generators have destroyed uncommitted work.
cd catbird-atproto && jj new

cargo build --locked --manifest-path ../mls-ds/Cargo.toml -p mls-codegen --bin gen-lexicons
GEN=../mls-ds/target/debug/gen-lexicons   # or "$CARGO_TARGET_DIR/debug/gen-lexicons"
python3 Scripts/regenerate.py generate --generator "$GEN"
python3 Scripts/regenerate.py check --generator "$GEN"   # a second run must match byte for byte
```

The script runs the generator into a temporary directory and gates `com_atproto::{space, memberspace, managedspace, personalspace}` behind the `namespace-atproto-space` feature. That gate is the one post-generation step, because `mls-codegen` cannot put a module behind a Cargo feature. It then runs `rustfmt --edition 2021`. `generate` replaces `src/generated/` and keeps the previous tree in the temporary directory; `check` compares every file with `src/generated/` and changes nothing. The script never rewrites generated declarations: fix generator bugs in `mls-ds/codegen`.

Do **not** regenerate with the workspace-level `./scripts/regenerate-atproto-types.sh` or a bare `cargo run -p mls-codegen -- --outdir catbird-atproto/src/generated`. Both skip the namespace gate and do not pin the rustfmt edition, so they do not reproduce the committed tree. `CODEGEN_PROVENANCE.md` records the current generator revision, input corpus and output hashes; update it with every regeneration.

After regenerating: `jj diff` to verify, then `cargo fmt --check`, `cargo test --locked --features streaming,namespace-atproto-space` and `cargo clippy --locked --all-targets --all-features`, then rebuild **every consumer** ([Consumers](#consumers)) and reconcile breakage. If output is wrong, `jj op undo` and fix the **lexicon or the generator** — never patch generated files. For the cross-language path (Swift/Kotlin too), use the `/regen-lexicons` skill, but take the Rust step from `Scripts/regenerate.py`.

## Source Map

```
src/
  lib.rs                  Hand-written crate root: re-exports + the `catbird::` ergonomic shim
                          (NSIDs, From<InputData> builders for mls_chat/bsky_chat). Editable.
  generated/              ALL generated — DO NOT EDIT
    builder_types.rs      Shared builder/helper types
    blue_catbird/         blue.catbird.* — MLS chat (mlsChat), bskychat, app types  [DEFAULT]
    com_atproto/          com.atproto.* — repo, sync, identity, server primitives
    site_standard/        site.standard.* — document, publication, graph, and theme types
    app_bsky/             app.bsky.* — Bluesky feed/actor/graph/notification types
    chat_bsky/            chat.bsky.* — Bluesky DM/convo types (see Gotchas: wiring deferred)
    tools_ozone/          tools.ozone.* — moderation
    place_stream/         place.stream.*
    com_germnetwork/      com.germnetwork.*
```

Not every namespace dir on disk is wired into the compiled surface — the inline `generated` module in `src/lib.rs` is the source of truth for what's active. `chat_bsky` is generated but its crate-module declaration is intentionally deferred until a Rust consumer needs Bluesky chat types (see Gotchas). The `catbird::` module in `lib.rs` is the curated, hand-written ergonomics layer (NSID constants, typed `Input`/`Output` aliases, `InputData → Input` converters) and **is** safe to edit.

## Consumers

Path-dependency consumers (regenerating types here may break their builds — rebuild them after any regen):

| Consumer | Cargo path |
|----------|------------|
| `catbird-mls` | `catbird-atproto = { path = "../catbird-atproto" }` |
| `nest/catbird` | `catbird-atproto = { path = "../../catbird-atproto" }` |
| `mls-ds`, `catbird-firehose`, others | path deps as needed |

When a lexicon contract changes, the reconcile loop is: edit lexicon → `Scripts/regenerate.py generate` then `check` → rebuild `catbird-atproto` → rebuild each consumer and fix call sites.

## Gotchas

- **Jacquard struct evolution breaks downstream literal init.** Adding **any** field to a generated struct — even `Option<T>` — breaks every consumer that uses `Foo { ... }` struct-literal initialization, because Rust requires all fields. A lexicon change that "just adds an optional field" is a breaking change for consumers. Prefer constructing via the `catbird::` `InputData` builders / `From` impls in `lib.rs` rather than naming generated structs directly, and expect to touch consumer call sites after a regen. (Long-term fix is upstream `#[non_exhaustive]` / `#[derive(Default)]` on generated types.)
- **`chat_bsky` is generated but not fully wired.** The `chat.bsky.*` types exist under `src/generated/chat_bsky/` but the module declaration is deferred. Wire it in (module decl + feature gate, mirroring `blue_catbird`) only when the first Rust consumer — BIRDaemon, nest chat-poll, a mod tool — actually needs it.
- **PetrelCatbird is the Catbird-private overlay.** Update `PetrelCatbird/lexicons/` for `blue.catbird.*` and `place.stream.*`; update `Petrel/generator/lexicons/` for public ATProto/Bluesky lexicons. The Rust script consumes both, matching the Swift/Kotlin manifest.
- **Always checkpoint before regenerating.** Generators have overwritten uncommitted work. `jj new` (or commit/stash) first; `jj diff` after; `jj op undo` to roll back.

## Coding Style

- `cargo fmt` + `cargo clippy` clean before committing (generated output is already `rustfmt`ed by `Scripts/regenerate.py`).
- Standard Rust conventions. The only files you should hand-edit are `src/lib.rs` and the `catbird::` shim within it — never `src/generated/`.
- Commit prefix: scope as `catbird-atproto:` (e.g. `catbird-atproto: wire chat_bsky namespace`). For lexicon-driven changes, the substantive edit belongs in the lexicon repo; the regenerated diff here is a follow-on.
